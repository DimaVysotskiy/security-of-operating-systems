# Раздел 5. Управление основными правами доступа пользователей к файловым ресурсам

<!-- Источник: 20261028_142232.jpg; стр. 94 -->

## 5.1. Цель раздела

**Цель раздела** — получить теоретические знания и практические навыки управления доступом к объектам файловой структуры с использованием базовой системы разграничения прав доступа ОС семейства Linux.

## 5.2. Теоретическая информация

> Операционные системы семейства Linux являются многопользовательскими.

Поэтому одним из важнейших механизмов, который должен обеспечивать безопасность обработки информации, является система управления дискреционными правами доступа к каталогам и файлам. Следует отметить, что существующая в ОС семейства Linux базовая система разграничения прав доступа имеет несколько ограниченные возможности.

Рассмотрим основные права доступа к объектам в ОС семейства Linux. Принцип организации прав доступа существенно отличается от реализации, существующей в ОС семейства Windows.

> **ВНИМАНИЕ!**
>
> С точки зрения Linux каталог является файлом специального типа.

<!-- Источник: 20261028_142235.jpg; стр. 95 -->

Каждый файл имеет три привилегии доступа. Ими являются:

1. Чтение. Эта привилегия разрешает прочесть, увидеть содержимое файла без возможности изменить его содержание. Для каталога право чтения позволяет получать список файлов и других каталогов, размещенных в нем.
2. Запись. Применительно к каталогам право записи дает возможность создавать или удалять файлы, размещенные в нем, а также создавать или удалять новые подкаталоги. Для файлов привилегия записи позволяет изменять их содержимое.
3. Выполнение. Право выполнения дает возможность выполнить программу. Этот атрибут устанавливается для программ или скриптов. С помощью этой привилегии операционная система понимает, что файл следует запускать именно как программу.

У этих привилегий есть числовые значения, которые можно использовать при установке прав доступа: чтение — r (4), запись — w (2), выполнение — x (1).

Для каждого файла предусмотрено три типа (роли) пользователей, для которых имеется возможность установить различные прав доступа:

1. владелец объекта (обозначение — u). Это пользователь, который создал файл (каталог), или же пользователь, которому была передана данная роль. Как правило, владелец имеет все права доступа к объекту. Назначить пользователя, владеющего объектом, может только root;
2. группа владельцев файла (каталога) (обозначение — g). Ей может быть любая группа пользователей, существующая в системе и указанная как владелец объекта: группа владельца объекта, появляющаяся автоматически при создании в системе пользователя (в которой, как правило, есть только один одноименный пользователь), или группы, специально созданные администратором безопасности и объединяющие нескольких пользователей для настройки многопользовательского доступа;
3. остальные пользователи (обозначение — o). Все остальные пользователи, кроме владельца и группы владельцев объекта.

<!-- Источник: 20261028_142241.jpg; стр. 96 -->

Также существуют специальные права доступа к файлам в Linux. Они используются для того, чтобы обычные пользователи могли осуществить запуск программы от имени суперпользователя ***root***, не зная его пароля:

- SUID — если этот флаг установлен, то при выполнении программы id пользователя, от которого она запущена, заменяется на id владельца файла. Фактически это позволяет обычным пользователям запускать программы от имени суперпользователя;
- SGID — этот флаг работает аналогично SUID. Разница заключается в том, что пользователь считается членом группы, с которой связан файл, а не групп, к которым он в действительности принадлежит. Если SGID-флаг установлен на каталог, то все файлы, созданные в нем, будут связаны с группой каталога, а не пользователя. Такой способ иногда используется для организации общих папок;
- Sticky-bit — этот флаг также используется для создания общих папок. Если он установлен, то пользователи могут только создавать, читать и выполнять файлы, но не могут удалять файлы, принадлежащие другим пользователям.

Также для задания прав доступа могут использоваться числовые комбинации из четырех чисел со значениями от 0 до 7. Первое число используется для задания специальных битов. SUID имеет числовое значение 4, SGID — числовое значение 2, а sticky bit — числовое значение 1. Если оно равно 0, то специальные биты не используются и его можно не указывать.

В этом случае числовая комбинация становится трехзначной.

Второе число описывает права пользователя-владельца. Третье значение описывает права доступа группы владельцев объекта. Четвертое описывает права доступа к объекту остальных пользователей. Числовое значение складывается из прав на чтение — 4, запись — 2, выполнение — 1. Например, можно указать такую комбинацию прав:

```text
chmod 2755 /somefolder
```

**chmod** — это одна из команд управления правами доступа, она будет рассмотрена далее. Краткое описание возможных для установки прав доступа к объектам приведено в таблице 5.1 [18].

<!-- Источник: 20261028_142243.jpg; стр. 97 -->

Для управления правами доступа используются следующие команды:

- **chmod** (сокр. англ. change mode — изменить режим) дает права доступа к объектам пользователям и группам;
- **chown** (сокр. англ. change owner — поменять владельца) позволяет изменить владельца объекта;
- **chgrp** (сокр. англ. change group — поменять группу) позволяет изменить группу владельцев объекта;
- **ls** — позволяет просматривать права доступа к каталогам и файлам.

Таблица 5.1. Описание прав доступа

| OCT | BIN | Строковое | Права на файл | Права на каталог |
| --- | --- | --- | --- | --- |
| 0 | 000 | `---` | Отсутствие прав | Отсутствие прав |
| 1 | 001 | `--x` | Право на исполнение | Право на доступ к файлам и атрибутам |
| 2 | 010 | `-w-` | Право на запись | Отсутствие прав |
| 3 | 011 | `-wx` | Право на запись и исполнение | Все права, кроме получения имен файлов |
| 4 | 100 | `r--` | Право на чтение | Право на получение имен файлов |
| 5 | 101 | `r-x` | Право на чтение и исполнение | Право на получение имен файлов и доступ к ним |
| 6 | 110 | `rw-` | Право на чтение и запись | Право на получение имен файлов |
| 7 | 111 | `rwx` | Все права | Все права |

Также могут применяться команды:

- **find** — позволяет находить пользователей, являющихся владельцами файлов;
- **newgrp** — временная установка текущей активной группы [62].

Первая тройка символов относится к владельцу объекта (пользователю root). Как правило, по умолчанию это комбинация rwx — полные права доступа.

Вторая тройка символов определяет права группы владельцев. По умолчанию она равна r-x, что означает возможность чтения данных и выполнения программ из соответствующего каталога.

Третья группа символов определяет права остальных пользователей, не относящихся к первым двум категориям. По умолчанию она также равна r-x, что позволяет просматривать файлы и запускать исполняемые объекты.

### Задание 5.2. Настроить права доступа к каталогу /home/work/total_data

**Выполнение:**

К каталогу /home/work/total_data должны иметь доступ только пользователи, входящие в группу managers. Доступ остальных пользователей, в том числе и входящих в группу specialists, должен отсутствовать.

Администратор безопасности должен иметь полный доступ к каталогу.

1. Измените группу владельцев объекта для каталога /home/work/total_data на managers. На данный момент группой владельцев является группа root.

<!-- Источник: 20261028_142256.jpg; стр. 100 -->

2. Выполните следующую команду из-под учетной записи *root*:

```text
wrk1 ~ # chgrp -R managers /home/work/total_data
```

3. Измените права доступа для группы владельцев managers, предоставив ей полный доступ к каталогу /home/work/total_data:

```text
wrk1 ~ # chmod -R g=rwx /home/work/total_data
```

Ключ -R используется для рекурсивного применения прав доступа на вложенные каталоги. Инструкция g=rwx позволяет дать полные права доступа именно для группы владельцев (на это указывает буква g).

4. Выполните просмотр прав доступа к каталогу /home/work и вложенных в него объектов с помощью команды **ls -la /home/work**. Обратите внимание на произошедшие изменения: изменились группа владельцев объекта /home/work/total_data и права доступа к нему.
5. Отнимите права доступа к каталогу у остальных пользователей с помощью команды:

```text
wrk1 ~ # chmod -R o=-r-w-x /home/work/total_data
```

Выражение o=-r-w-x понимается следующим образом: отнять все права доступа (наличие знаков «-» перед буквами, обозначающими соответствующие привилегии, говорит о том, что права доступа забираются) у группы остальные пользователи (буква o соответствует группе others).

Вновь проверьте установленные права доступа с помощью команды:

```text
wrk1 ~ # ls -la /home/work
```

Обратите внимание на значительное изменение прав доступа к каталогу /home/work/total_data по сравнению с предыдущим вызовом этой же команды.

6. Установите права доступа на каталог /home/work/daily_data так, чтобы группа specialists получила полный доступ к нему. Остальные пользователи должны иметь доступ на чтение данных.

<!-- Источник: 20261028_142258.jpg; стр. 101 -->

В окне **Терминала** введите команду:

```text
wrk1 ~ # chmod -R 0775 /home/work/daily_data
```

Измените группу владельцев каталога /home/work/daily_data/ на specialists, выполнив команду:

```text
wrk1 ~ # chgrp -R specialists /home/work/daily_data
```

7. Для каталога /home/work/tasks определите права так, чтобы группа пользователей managers могла редактировать данные, а specialists просматривать данные. Для этого группой владельцев объекта укажите группу managers. Остальным пользователям предоставим права чтения. Выполните команды:

```text
wrk1 ~ # chmod -R 7775 /home/work/tasks
wrk1 ~ # chgrp -R managers /home/work/tasks
```

В данном случае права доступа описываются четырехзначной числовой последовательностью. Первое число из четырех описывает применение специальных прав доступа (SUID — 4, SGID — 2, sticky bit - 1).

> **ВНИМАНИЕ!**
>
> Без необходимости специальные биты использовать не следует. Приведенные ниже команды указаны с целью ознакомления с возможностями системы управления правами доступа к объектам, существующей в ОС семейства Linux.

Отметим, что для установки SUID с помощью символьных выражений используется chmod u+s, SGID — chmod g+s, для sticky bit используется chmod +t, после чего указывается наименование требуемого каталога или файла. Затем указываются числа, описывающие: права владельца, права группы владельцев, права остальных пользователей.

При необходимости скорректируйте принадлежность пользователей к основным группам. Основная группа указывается сразу за идентификатором пользователя, как показано на рисунке 5.2.


Рис. 5.2. Информация о принадлежности пользователя к группам

> **ВНИМАНИЕ!**
>
> Причина замены основной группы у пользователей состоит в том, что при создании пользователя автоматически создается одноименная группа. Однако в ней, как правило, имеется только один пользователь. В то же время группы пользователей существуют для того, чтобы облегчать администрирование прав доступа, для чего в них могут добавить нескольких пользователей с аналогичными правами доступа.

При создании файла владельцем объекта становится тот, кто его создал. Группой владельцев объекта становится группа, которая является основной для данного пользователя. Но она должна быть основной и для других пользователей с однотипными правами доступа, чтобы они также могли обрабатывать файлы.

Таким образом, возникает необходимость создания отдельных групп и добавления в них пользователей. Только так можно обеспечить многопользовательский доступ к объектам.

Рис. 5.3. Установленные биты SGID

Эти специальные права были установлены с целью демонстрации возможностей системы разграничения прав доступа. На данный момент они не нужны, поэтому их следует убрать. Чтобы удалить специальные биты, последовательно выполните следующие команды:

```text
wrk1 ~ # chmod -R g-s /home/work/tasks
```

Проверьте, как изменились права доступа. Был удален бит SGID.

Для удаления бита SUID, установленного для каталога /home/work/tasks, используется запись в форме u-s:

```text
wrk1 ~ # chmod -R u-s /home/work/tasks
```

После выполнения команды опять проверьте права доступа к каталогу.

Для удаления sticky_bit выполните команду:

```text
wrk1 ~ # chmod -t /home/work/tasks/
```

После выполнения команды опять проверьте права доступа к каталогу /home/work/tasks. Также для удаления sticky bit можно использовать маску прав доступа из четырех чисел:

```text
wrk11 ~ # chmod -R 0775 /home/work/tasks
```

Проверьте установленные права доступа к каталогу /home/work/tasks.

Проведенные тесты показали, что стандартных возможностей распределения прав в Linux в ряде случаев бывает недостаточно для обеспечения многопользовательского доступа к объектам. Чтобы обеспечить возможность совместного редактирования файла, созданного одним из пользователей, требуется дополнительная настройка прав других учетных записей. Причем эта настройка может быть выполнена пользователем, не являющимся администратором.

Данное обстоятельство не всегда бывает приемлемым, поскольку пользователь сможет выполнять некоторые функции администрирования, самостоятельно меняя права доступа к защищаемым файлам и каталогам. В ряде случаев самовольное изменение прав доступа к обрабатываемым объектам является опасным явлением, которое противоречит концепции централизованного администрирования прав доступа к защищаемым информационным ресурсам.

Для решения этой проблемы скорректируем значение константы umask на системном уровне.

> **ВНИМАНИЕ!**
>
> Значение константы umask отнимается от максимально возможной комбинации прав **777**, существующей в Linux-системах, для вновь создаваемых объектов. Можно сказать, что umask — это способ уменьшения права доступа, которые получают новые файлы, с целью обеспечения их безопасности [88].

### Задание 5.4. Изучить воздействие константы umask на права доступа к вновь создаваемым объектам

**Выполнение:**

1. Выполните в командной строке переподключение к учетной записи root с помощью команды **su -**.

2. Используя редакторы vim или nano, откройте файл /etc/profile.

Рис. 5.6. Изменение константы umask в файле /etc/profile

При создании объекта от максимально возможного значения прав 777 (wrx для владельца файла, группы владельцев и остальных пользователей) отнимается значение 022. Получится комбинация прав 755. Таким образом, право изменять объект будет только у владельца объекта.

Члены группы владельцев и группы других пользователей будут иметь права на чтение файла. Смысл внесенных изменений состоит в том, чтобы группа владельцев также могла изменять файлы владельца. Данная ситуация продемонстрирована на рисунке 5.5.

Имеется также другой способ установки значения umask.

4. С помощью редактора vim создайте файл /etc/profile.d/umask.sh, состоящий из одной строки UMASK=002, как показано на рис. 5.7:

```text
UMASK=0002
"/etc/profile.d/umask.sh" 1L, 11B           1,1  Весь текст
```
