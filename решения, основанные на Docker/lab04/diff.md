Номер `5.2.8` означает шаг 8 задания 5.2. Буквы отмечают действия без собственного номера. Формулировки сокращены. Статусы описывают текущее решение по [Dockerfile](Dockerfile), [Compose](../compose.yaml) и [README.md](README.md).

- **Выполнено** — результат предусмотрен в стенде или инструкции, в том числе другим способом.
- **Частично** — перенесена часть требований.
- **Опущено** — практический шаг отсутствует.

## Задание 5.2. Настроить права доступа к каталогу `/home/work/total_data`

| Пункт | Что требуется в исходной методичке | Статус и пояснение для Docker |
| --- | --- | --- |
| 5.2.1 | Назначить `managers` группой-владельцем `total_data`. | **Выполнено** (в контейнере). Студент меняет группу с `root` на `managers`. |
| 5.2.2 | От `root` выполнить `chgrp -R managers /home/work/total_data`. | **Выполнено** (в контейнере). Используется `chgrp managers /home/work/total_data`. На этом шаге каталог пуст. |
| 5.2.3 | Дать группе полный доступ через `chmod -R g=rwx`. | **Выполнено** (в контейнере). Студент выполняет `chmod g=rwx` на самом каталоге. |
| 5.2.4 | Просмотреть владельца, группу и права после изменения. | **Выполнено** (в контейнере). `ls -ld /home/work/total_data` показывает изменённый каталог. Полный список просматривается в шаге 5.2.9. |
| 5.2.5 | Снять права с остальных пользователей и повторить проверку. | **Выполнено** (в контейнере). Через `chmod o=` студент снимает все права у остальных и смотрит результат через `ls -ld`. |
| 5.2.6 | Назначить `specialists` группой `daily_data`, дать ей полный доступ и сохранить чтение для остальных. | **Выполнено** (в контейнере). Используются `chgrp specialists` и `chmod 0775`. Остальным доступны чтение и проход, создание файлов ограничено. |
| 5.2.7 | Назначить для `tasks` группу `managers` и режим `7775`, чтобы увидеть специальные биты. | **Выполнено** (в контейнере). Студент меняет группу, затем устанавливает режим на самом каталоге и просматривает результат. |
| 5.2.8 | Проверить основные группы всех четырёх пользователей и при необходимости скорректировать их. | **Частично** (Dockerfile и команды студента). При сборке `user1` и `user2` получают основную группу `managers`, `user3` и `user4` — `specialists`. Студент проверяет по одному представителю каждой группы через `id user2` и `id user3`. |
| 5.2.9 | Просмотреть итоговое состояние каталогов через `ls -la /home/work`. | **Выполнено** (в контейнере). Студент проверяет права каждого каталога и находит обозначения `s` и `t` у `tasks`. |
| 5.2.9а | Снять SGID, SUID и sticky bit с `tasks`, проверяя результат после каждого шага. | **Выполнено** (в контейнере). Используются `chmod g-s`, `chmod u-s` и `chmod -t`, после каждой команды выполняется `ls -ld`. |
| 5.2.10 | Завершить сеанс администратора. | **Опущено** (административная оболочка остаётся открытой для следующего задания, отдельные команды от имени пользователей запускаются через `runuser`). |
| 5.2.10а | Поместить сведения о настроенных правах в отчёт. | **Выполнено** (отчёт). Сохраняется вывод `ls` после изменения прав. |
