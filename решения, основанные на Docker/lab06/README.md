# Лабораторная работа № 6. Контроль целостности

Цель — сравнить два состояния файлов с помощью Osec, посмотреть смену журналов и запланировать проверки в `cron`. Нумерация заданий сохранена из [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-06.md>).

Из каталога с `compose.yaml`:

```bash
docker compose up -d --build lab06
docker compose exec lab06 bash
```

[Dockerfile](Dockerfile) устанавливает Osec, утилиту формирования отчётов, `cron` и редактор. В образе есть контрольный каталог `/home/lab06-baseline`, каталог `/home/test3` с двумя файлами и начальный список наблюдения `/etc/lab06/dirs.conf`. При запуске контейнера стартует `crond`. Базу и свои задания `cron` вы создадите вручную.

В книге используется веб-интерфейс Alterator. Здесь ту же проверку файлов выполняет [Osec из командной строки](https://www.basealt.ru/knowledge_base/lknv.11102-01-99-01-rukovodstvo-po-kompleksu-sredstv-zashhity.html). Сканирование запускается от имени пользователя `osec` и работает с учебными каталогами внутри контейнера. Остальные команды выполняйте в оболочке `root` контейнера, если не указано иное.

## 7.1. Проверьте инструменты

```bash
rpm -q osec osec-mailreport vixie-cron
osec --version
command -v osec_reporter crontab crond
```

Эти команды заменяют установку модуля и проверку веб-сервера из книги. Утилиты уже установлены при сборке.

## 7.2. Создайте первый журнал

```bash
cat /etc/lab06/dirs.conf
lab06-run-osec
ls -l /var/lib/lab06-osec
cat /var/log/osec.log
```

В списке пока только `/home/lab06-baseline`. При первом запуске ищите `Init database for /home/lab06-baseline`. База хранит состояние файлов, а журнал — результат конкретной проверки.

## 7.3. Добавьте объект и проверьте изменения

1. Посмотрите подготовленные файлы и добавьте каталог в список. Первое сканирование нового каталога зафиксирует его исходное состояние:

   ```bash
   ls -l /home/test3
   printf '%s\n' '/home/test3' >> /etc/lab06/dirs.conf
   lab06-run-osec
   ls -l /var/log/osec.log*
   ```

2. Измените оба файла и выполните новую проверку:

   ```bash
   printf '%s\n' 'Изменение первого файла' >> /home/test3/asd.txt
   printf '%s\n' 'Изменение второго файла' >> /home/test3/qwe.txt
   lab06-run-osec
   ```

   Найдите в отчёте `Changed controlled files` и две изменённые записи.

3. Повторите проверку без дальнейших правок:

   ```bash
   lab06-run-osec
   cat /var/log/osec.log.1
   ```

   Новый отчёт должен показать `No changes`: предыдущая проверка уже записала новое состояние в базу. Отчёт об изменениях теперь в `osec.log.1`. Скрипт сохраняет до пяти предыдущих отчётов.

## 7.4. Изучите список путей и настройки

Страницы с выполнением задания 7.4 отсутствуют в исходниках. В этом стенде изучите конфигурацию и команду запуска:

```bash
cat /etc/lab06/dirs.conf
sed -n '1,25p' /usr/local/sbin/lab06-run-osec
osec --help
```

Найдите параметры `-f` (список путей), `-D` (каталог базы) и `-t` (алгоритм хеширования). В стенде задан SHA-256. Для эксперимента с другим алгоритмом используйте отдельный каталог базы, чтобы результаты сравнивались с состоянием, снятым тем же алгоритмом.

## 7.5. Проверьте редактор

В исходниках есть только заголовок этого задания. Для работы с `crontab` в образе задан `EDITOR=nano`. Проверьте значение командой `printenv EDITOR`. Если нужно указать редактор для одного вызова, запустите `EDITOR=nano crontab -e`.

## 7.6. Настройте проверку по расписанию

Запустите `crontab -e` и добавьте:

```cron
MAILTO=""
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
@reboot /usr/local/sbin/lab06-run-osec >> /var/log/osec-cron.log 2>&1
10 13 * * * /usr/local/sbin/lab06-run-osec >> /var/log/osec-cron.log 2>&1
```

Проверьте установки через `crontab -l`, время контейнера через `date`. Строка `10 13 * * *` задаёт ежедневную проверку в 13:10 по часам контейнера. Для быстрой демонстрации временно замените `10 13 * * *` на `* * * * *`, измените один из файлов в `/home/test3` и дождитесь следующей минуты. Посмотрите результат:

```bash
tail -n 40 /var/log/osec-cron.log
cat /var/log/osec.log
```

Верните расписание на 13:10. Для проверки `@reboot` снова измените файл, выйдите из оболочки и выполните **на хосте** `docker compose restart lab06`. Затем войдите снова и проверьте новый отчёт: в этом стенде запуск демона `cron` заменяет загрузку отдельной ОС. Обычный перезапуск сохраняет расписание, базу и журналы контейнера.

В отчёт приложите начальный журнал, обнаруженное изменение, последующий отчёт без изменений и расписание. Сохраните нужный отчёт до следующих проверок, поскольку журналы ротируются.
