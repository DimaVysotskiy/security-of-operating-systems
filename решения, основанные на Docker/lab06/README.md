# Лабораторная работа № 6. Контроль целостности

Цель — сравнить два состояния файлов с помощью Osec, посмотреть смену журналов и запланировать проверки в `cron`. Нумерация заданий сохранена из [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-06.md>).

## Предусловия

Ниже описана подготовка образа и контейнера. В [diff.md](diff.md) показано, какие шаги перенесены в Dockerfile и какие выполняет студент.

### 1. Базовый образ и пакеты (задание 7.1)

Используется `alt:p11`. При сборке APT обновляет индексы штатных репозиториев и устанавливает `osec` для проверки, `osec-mailreport` для формирования отчёта, `util-linux` для `runuser` и `flock`, `vixie-cron` для расписания и `nano` для редактирования. После установки скачанные архивы и индексы удаляются. [Dockerfile, строки 1–8](Dockerfile#L1-L8)

### 2. Учебные файлы, список наблюдения и каталог базы (задания 7.2–7.3)

Dockerfile создаёт `/home/lab06-baseline/base.txt` и два непустых файла `/home/test3/asd.txt` и `/home/test3/qwe.txt`. Все три файла доступны для чтения с правами `0644`. Каталог базы `/var/lib/lab06-osec` создаётся с правами `0750` для пользователя и группы `osec`. Записи в базе появятся при первом сканировании, которое запустит студент. [Dockerfile, строки 11–18](Dockerfile#L11-L18)

В `/etc/lab06/dirs.conf` изначально указан только `/home/lab06-baseline`. Путь `/home/test3` студент добавит после первой проверки. [Dockerfile, строки 20–24](Dockerfile#L20-L24), [dirs.conf, строка 1](dirs.conf#L1)

### 3. Запуск Osec и хранение отчётов (задания 7.2–7.4)

В образе доступна команда `lab06-run-osec`. Она не даёт двум проверкам запуститься одновременно, запускает Osec от имени `osec` с SHA-256 и форматирует результат через `osec_reporter`. После успешного завершения текущий отчёт записывается в `/var/log/osec.log`, а предыдущие хранятся как `osec.log.1`–`osec.log.5`. [Dockerfile, строки 20–24](Dockerfile#L20-L24), [run-osec.sh, строки 5–26](run-osec.sh#L5-L26)

### 4. Редактор и планировщик (задания 7.5–7.6)

Если установленный пакет добавил `/etc/cron.d/osec`, Dockerfile переносит этот файл в `/etc/lab06/osec.cron.example`. Так автоматическая проверка Osec начнётся после того, как студент настроит своё расписание. Для `crontab -e` задан `EDITOR=nano`. При запуске контейнера `crond -n` работает на переднем плане. [Dockerfile, строка 14](Dockerfile#L14), [Dockerfile, строки 26–27](Dockerfile#L26-L27)

## Запуск стенда

Выполните на хосте из каталога с `compose.yaml`:

```bash
docker compose up -d --build lab06
docker compose exec lab06 bash
```

[Compose](../compose.yaml#L52-L57) запускает контейнер `lab06` с именем хоста `wrk1`. При создании Docker копирует подготовленные файлы в отдельный том `/home`. В нём Osec может повторно проверить изменённые файлы и их атрибуты. Том сохраняется при остановке и перезапуске. Для чистого повторения работы выполните на хосте `docker compose up -d --force-recreate --renew-anon-volumes --no-deps lab06`. Эта команда заменит контейнер и его учебные данные.

## Практические задания

В методичке для запуска проверок используется веб-интерфейс Alterator. В стенде студент запускает Osec из терминала. Команды выполняйте в оболочке `root` контейнера, если в задании не указано другое место запуска. [Руководство ALT](https://www.basealt.ru/knowledge_base/lknv.11102-01-99-01-rukovodstvo-po-kompleksu-sredstv-zashhity.html)

### 7.1. Проверьте инструменты

```bash
rpm -qf "$(command -v osec)" "$(command -v osec_reporter)"
rpm -q vixie-cron
osec --version
command -v osec_reporter crontab crond
```

Утилиты уже установлены при сборке. Команда `rpm -qf` показывает фактических поставщиков программ. В ALT p11 ими могут быть `osec-cert` и `osec-cert-mailreport`.

### 7.2. Создайте первый журнал

```bash
cat /etc/lab06/dirs.conf
lab06-run-osec
ls -l /var/lib/lab06-osec
cat /var/log/osec.log
```

В списке пока только `/home/lab06-baseline`. При первом запуске ищите `Init database for /home/lab06-baseline`. База хранит состояние файлов, а журнал — результат конкретной проверки.

### 7.3. Добавьте объект и проверьте изменения

1. Посмотрите подготовленные файлы и добавьте каталог в список. Первое сканирование нового каталога зафиксирует его исходное состояние:

   ```bash
   ls -l /home/test3
   printf '%s\n' '/home/test3' >> /etc/lab06/dirs.conf
   lab06-run-osec
   ls -l /var/log/osec.log*
   ```

2. Измените оба файла и выполните новую проверку:

   ```bash
   printf '%s\n' 'Изменение первого файла' >> /home/test3/asd.txt
   printf '%s\n' 'Изменение второго файла' >> /home/test3/qwe.txt
   lab06-run-osec
   ```

   Найдите в отчёте `Changed controlled files` и две изменённые записи.

3. Повторите проверку без дальнейших правок:

   ```bash
   lab06-run-osec
   cat /var/log/osec.log.1
   ```

   Новый отчёт должен показать `No changes`: предыдущая проверка уже записала новое состояние в базу. Отчёт об изменениях теперь в `osec.log.1`. Скрипт сохраняет до пяти предыдущих отчётов.

### 7.4. Изучите список путей и настройки

Страницы с выполнением задания 7.4 отсутствуют в исходниках. В этом стенде изучите конфигурацию и команду запуска:

```bash
cat /etc/lab06/dirs.conf
sed -n '1,25p' /usr/local/sbin/lab06-run-osec
osec --help
```

Найдите параметры `-f` (список путей), `-D` (каталог базы) и `-t` (алгоритм хеширования). В стенде задан SHA-256. Для эксперимента с другим алгоритмом используйте отдельный каталог базы, чтобы результаты сравнивались с состоянием, снятым тем же алгоритмом.

### 7.5. Проверьте редактор

В исходниках есть только заголовок этого задания. Для работы с `crontab` в образе задан `EDITOR=nano`. Проверьте значение командой `printenv EDITOR`. Если нужно указать редактор для одного вызова, запустите `EDITOR=nano crontab -e`.

### 7.6. Настройте проверку по расписанию

Запустите `crontab -e` и добавьте:

```cron
MAILTO=""
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
@reboot /usr/local/sbin/lab06-run-osec >> /var/log/osec-cron.log 2>&1
10 13 * * * /usr/local/sbin/lab06-run-osec >> /var/log/osec-cron.log 2>&1
```

Проверьте установки через `crontab -l`, время контейнера через `date`. Строка `10 13 * * *` задаёт ежедневную проверку в 13:10 по часам контейнера. Для быстрой демонстрации временно замените `10 13 * * *` на `* * * * *`, измените один из файлов в `/home/test3` и дождитесь следующей минуты. Посмотрите результат:

```bash
tail -n 40 /var/log/osec-cron.log
cat /var/log/osec.log
```

Верните расписание на 13:10. Для проверки `@reboot` снова измените файл, выйдите из оболочки и выполните **на хосте** `docker compose restart lab06`. Затем войдите снова и проверьте новый отчёт: в этом стенде запуск демона `cron` заменяет загрузку отдельной ОС. Обычный перезапуск сохраняет расписание, базу и журналы контейнера.
