# Лабораторная работа № 3. Работа с группами учётных записей

Цель — научиться создавать локальные группы, менять основную и дополнительные группы пользователя и проверять, как членство влияет на доступ к файлу. Нумерация заданий сохранена из [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-03.md>).

## Предусловия

Следующие настройки применяются при сборке [Dockerfile](Dockerfile). В [diff.md](diff.md) показано, какие шаги взяты из методички и что студент выполняет внутри контейнера.

### 1. Базовый образ и утилиты (подготовка к заданию 4.4)

Используется образ `alt:p11`. При сборке APT обновляет индексы штатных репозиториев и устанавливает пакет `shadow-groups` с командой `gpasswd`. После установки скачанные архивы и индексы удаляются. [Dockerfile, строки 1–8](Dockerfile#L1-L8)


### 2. Учётные записи и исходное членство (подготовка к заданиям 4.1 и 4.3)

Dockerfile использует существующую группу `users` или создаёт её, если она отсутствует. Затем создаёт `user1`–`user4` без заданных паролей. У каждого пользователя есть одноимённая основная группа, домашний каталог в `/home`, оболочка Bash и дополнительная группа `users`. Это исходное состояние для сравнения `usermod -G` и `usermod -a -G`. [Dockerfile, строки 11–15](Dockerfile#L11-L15)


### 3. Пользовательские группы (задание 4.2)

Dockerfile создаёт `managers`, `specialists` и `tests` через `groupadd`. При первом входе эти группы пусты. Студент проверяет их список, затем меняет членство вручную. [Dockerfile, строки 18–21](Dockerfile#L18-L21)


### 4. Файл для проверки доступа (задание 4.4)

Dockerfile создаёт каталог `/opt/lab03` с правами `0755` и записывает строку «Учебный файл группы tests» в `/opt/lab03/test.txt`. Владелец файла — `root`, группа — `tests`, права — `0640`. Участники `tests` могут читать файл. Каталог доступен для прохода, поэтому результат проверки зависит от прав самого файла и членства в группе. [Dockerfile, строки 24–28](Dockerfile#L24-L28)


## Запуск стенда

Выполните на хосте из каталога с `compose.yaml`:

```bash
docker compose up -d --build lab03
docker compose exec lab03 bash
```

[Compose](../compose.yaml) запускает контейнер `lab03` с именем хоста `wrk1`. Команда `sleep infinity` из Dockerfile удерживает его запущенным между сеансами.

## Практические задания

Все команды в заданиях ниже выполняются от `root` **внутри** контейнера.

### 4.1. Просмотрите список групп

```bash
cat /etc/group
cat /etc/passwd
id user1
```

Найдите запись `user1` в `/etc/passwd`. Четвёртое поле — GID основной группы. Сопоставьте его с третьим полем записи в `/etc/group`. Четвёртое поле в `/etc/group` перечисляет явно записанных членов группы. Например, `user1` указан в записи группы `users`, но может отсутствовать в списке членов своей основной группы: связь с ней уже задана в `/etc/passwd`. Числа UID и GID используйте из своего контейнера.

Найдите системную группу `wheel`. В ALT её могут использовать политики доступа к административным командам, например `su`. Само членство в `wheel` не присваивает пользователю UID 0. Политики `wheel` в этой работе не меняем.

### 4.2. Проверьте созданные пользовательские группы

```bash
groupadd -h
grep -E '^(managers|specialists|tests):' /etc/group
```

Найдите команды `groupadd` в Dockerfile. Запишите имена и GID созданных групп. У всех трёх список членов пока пуст.

### 4.3. Добавьте пользователей в группы

1. Сравните вывод `groups` и `id`. Проверьте, что у `user1` и `user2` есть дополнительная группа `users`:

   ```bash
   usermod -h
   groups user1
   id user1
   id user2
   ```

2. Добавьте `user1` в `managers` без `-a`, а `user2` — с `-a`:

   ```bash
   usermod -G managers user1
   id user1
   usermod -a -G managers user2
   id user2
   ```

   У `user1` группа `users` исчезнет из списка дополнительных групп, а у `user2` сохранится. Основные группы на этом шаге не изменятся.

3. Верните `user1` в `users`, назначьте `managers` основной группой для `user1` и `user2`, затем добавьте `user3` и `user4` в `specialists`:

   ```bash
   usermod -a -G users user1
   usermod -g managers user1
   usermod -g managers user2
   usermod -a -G specialists user3
   usermod -a -G specialists user4
   id user1
   id user2
   id user3
   id user4
   ```

   По полю `gid` проверьте основные группы. Для `user3` и `user4` группы остались одноимёнными, а `specialists` появилась среди дополнительных.

### 4.4. Управляйте членством и проверьте доступ к файлу

1. Посмотрите права учебного файла, созданного при сборке. Права `0640` разрешают владельцу читать и писать, группе — читать, остальным — ничего. Права `0755` на каталог позволяют `user2` пройти к файлу.

   ```bash
   ls -ld /opt/lab03
   ls -l /opt/lab03/test.txt
   ```

2. Проверьте чтение от имени `user2`. До добавления в `tests` ожидается отказ в доступе:

   ```bash
   runuser -u user2 -- cat /opt/lab03/test.txt
   ```

3. Добавьте `user2` и `user3` в `tests`, проверьте их членство и повторите чтение. Теперь `user2` должен увидеть содержимое файла:

   ```bash
   usermod -a -G tests user2
   usermod -a -G tests user3
   id user2
   id user3
   runuser -u user2 -- cat /opt/lab03/test.txt
   ```

4. Исключите обоих пользователей из `tests` через `gpasswd -d`. Убедитесь, что остальные группы сохранились. Последняя проверка чтения снова должна закончиться отказом:

   ```bash
   gpasswd -d user2 tests
   gpasswd -d user3 tests
   id user2
   id user3
   runuser -u user2 -- cat /opt/lab03/test.txt
   ```

   Каждый вызов `runuser` запускает новую команду с актуальным списком групп. В уже запущенной оболочке список групп процесса не обновляется автоматически.

5. Удалите учебный файл, затем группу и проверьте, что записи группы больше нет. Для `tests` создавалась только группа, без одноимённой учётки.

   ```bash
   rm /opt/lab03/test.txt
   groupdel tests
   grep '^tests:' /etc/group
   ```

   При успешном удалении `grep` ничего не выведет.

## Перезапуск и сброс

Выйдите из контейнера командой `exit`. Из каталога с `compose.yaml` команда `docker compose restart lab03` перезапускает существующий контейнер и сохраняет изменения. Чтобы начать работу заново, пересоздайте только этот контейнер из собранного образа:

```bash
docker compose up -d --force-recreate --no-deps lab03
docker compose exec lab03 bash
```
