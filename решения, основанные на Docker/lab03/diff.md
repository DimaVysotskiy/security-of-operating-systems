# Лабораторная работа № 3. Работа с группами учётных записей

Сопоставление [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-03.md>) со стендом Docker.

Номер `4.3.2` означает шаг 2 задания 4.3. Буквы отмечают действия без собственного номера в источнике. Формулировки сокращены. Статусы описывают текущее решение по [Dockerfile](Dockerfile), [Compose](../compose.yaml) и [README.md](README.md).

- **Выполнено** — результат предусмотрен в стенде или в инструкции, в том числе другим способом.
- **Частично** — перенесена часть требований.
- **Опущено** — практический шаг отсутствует.
- **Добавлено** — действие есть в Docker-лабораторной сверх исходной методички.

## Цель и теоретическая информация

| Тема | Где разобрано в Docker-лабораторной |
| --- | --- |
| Для чего нужны системные и пользовательские группы | Задание 4.1 и контрольные вопросы. Состав системных групп проверяется в `/etc/group`; таблица 4.1 остаётся в методичке. |
| Основная и дополнительные группы | Задания 4.1 и 4.3. Студент сопоставляет GID с записями в `/etc/group`, затем меняет основную и дополнительные группы отдельно. |
| Группа `wheel` | Задание 4.1. Группу находят в `/etc/group` и разбирают её назначение. Переключение через `su` в лабораторной не проверяется. |

## Задание 4.3. Выполните добавление пользователей в группы

| Пункт | Что требуется в исходной методичке | Статус и пояснение для Docker |
| --- | --- | --- |
| 4.3.1 | Изучить справку `usermod`, сравнить `groups` и `id`, добавить `user1` в `managers` без ключа `-a`. | **Выполнено** (Dockerfile и команды студента). При сборке `user1`–`user4` добавляются в `users`. Студент проверяет исходное членство и выполняет `usermod -G managers user1`. |
| 4.3.2 | Проверить группы `user1`, затем добавить `user2` в `managers` с ключом `-a`. | **Выполнено** (в контейнере). Студент проверяет, что у `user1` группа `users` исчезла, а у `user2` сохранилась. |
| 4.3.3 | Сравнить результаты и восстановить членство `user1` в `users`. | **Выполнено** (в контейнере). Студент сравнивает вывод `id` и возвращает членство командой `usermod -a -G users user1`. |
| 4.3.4 | Сделать `managers` основной группой `user1`. | **Выполнено** (в контейнере). Студент выполняет `usermod -g managers user1` и проверяет поле `gid`. |
| 4.3.5 | Сделать `managers` основной группой `user2`. | **Выполнено** (в контейнере). Студент выполняет `usermod -g managers user2` и проверяет поле `gid`. |
| 4.3.6 | Добавить `user3` и `user4` в `specialists`, сохранив другие группы. | **Выполнено** (в контейнере). Студент использует `usermod -a -G specialists` и проверяет результат через `id`. `specialists` остаётся дополнительной группой. |
| 4.3.6а | Приложить сведения о членстве к отчёту. | **Выполнено** (отчёт). Инструкция запрашивает вывод `id` до и после применения `-G` и `-a -G`. |

## Задание 4.4. Управление принадлежностью пользователей к группам

| Пункт | Что требуется в исходной методичке | Статус и пояснение для Docker |
| --- | --- | --- |
| 4.4.1 | Добавить `user2` и `user3` в дополнительную группу `tests` с ключом `-a`. | **Выполнено** (в контейнере). Студент использует `usermod -a -G tests` для обеих учётных записей. |
| 4.4.2 | Проверить результат командами `id`. | **Выполнено** (в контейнере). Студент проверяет `id user2` и `id user3`. |
| 4.4.3 | Сопоставить результат с рис. 4.3. | **Выполнено** (в контейнере). В выводе обеих команд `id` должна появиться группа `tests`. Состав прочих групп и числовые идентификаторы берутся из стенда. `specialists` у `user3` остаётся дополнительной группой, как настроено в 4.3. |
| 4.4.4 | Исключить `user2` и `user3` из `tests` через `gpasswd -d`. | **Выполнено** (Dockerfile и команды студента). Пакет `shadow-groups` устанавливается при сборке, команды `gpasswd -d user2 tests` и `gpasswd -d user3 tests` выполняются вручную. |

| 4.4.7а | Ознакомиться с управлением локальными группами в Центре управления системой. | **Опущено** (стенд работает через командную строку, действия с группами выполняются командами Linux). |
| 4.4.б | Проверить чтение файла в зависимости от членства в `tests`. | **Добавлено** (Dockerfile и команды студента). При сборке создаются каталог `/opt/lab03` с правами `0755` и файл `test.txt` с владельцем `root:tests` и правами `0640`. Студент проверяет чтение от имени `user2` через `runuser` до добавления в группу, после добавления и после исключения. |
