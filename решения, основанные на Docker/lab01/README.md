# Лабораторная работа № 1. Первоначальная настройка ОС

Цель — сравнить состав пакетов до и после обновления и настроить связь между двумя рабочими станциями. Нумерация заданий сохранена из [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-01.md>).

Из каталога с `compose.yaml`:

```bash
docker compose up -d --build lab01
docker compose exec lab01 bash
```

[Dockerfile](Dockerfile) подготавливает ALT Linux p11, учётную запись `admin` без заданного пароля, инструменты APT и диагностики сети, каталог для отчёта и скрипт снимка. Compose даёт станции `wrk1` два интерфейса: один для выхода наружу через Docker, другой для учебной сети `192.168.101.0/24` со статическим адресом `192.168.101.11`. Снимки, обновление и эксперимент с адресом выполняются внутри контейнера. Команды ниже выполняйте там от `root`, если явно не указано, что команда запускается на хосте.

## 2.1. Зафиксируйте исходное состояние

```bash
id admin
lab01-snapshot before
ls -la /etc/apt/sources.list.d
cat /home/admin/version_1/{os-release,kernel,repositories}.txt
rpm -q apt rpm
```

В `packages.txt` сохраняется список установленных RPM с версиями. `/etc/os-release` описывает образ ALT, а `uname` показывает ядро Linux, на котором запущен контейнер. Вход в оболочку через Compose заменяет установку рабочей станции и переключение через `su`.

## 2.2. Обновите пакеты

```bash
apt-repo
grep -Eh '^[[:space:]]*rpm[[:space:]]' /etc/apt/sources.list /etc/apt/sources.list.d/*.list
apt-get update
apt-get install apt rpm
apt-get dist-upgrade
```

Проверьте, что подключена ветка p11. Если по заданию нужно сменить зеркало, отредактируйте соответствующий файл в `/etc/apt/sources.list.d/` редактором `nano`, оставив ветку p11 и отключив дублирующие записи. Снова проверьте вывод `apt-repo` перед обновлением. `apt-get update` обновляет индексы, а `dist-upgrade` меняет установленные пакеты. См. [документацию ALT по настройке APT](https://docs.altlinux.org/ru-RU/platform/11.0/html/alt-platform/nastrojka_spiska_repozitoriev_apt.html).

Пункты с Synaptic, Центром управления системой, `update-kernel` и перезагрузкой ОС относятся к стенду на виртуальных машинах. Контейнер использует общее ядро, поэтому обновление пакетов внутри него не обновляет работающее ядро.

## 2.3. Сравните состояние после обновления

```bash
lab01-snapshot after
diff -ru /home/admin/version_1 /home/admin/version_2
```

Запишите, что изменилось в списке пакетов и источников и что произошло с версией ядра. Отсутствие различий в списке пакетов допустимо, если они уже актуальны для подключённого репозитория. Код выхода `diff` равен 1, если найдены различия.

## 2.4. Проверьте имя рабочей станции

```bash
hostname
cat /etc/hostname
```

Ожидается `wrk1`. Здесь имя задаёт параметр `hostname` в Compose при создании контейнера. Редактирование `/etc/hostname` изнутри само по себе не меняет текущее имя, которое возвращает `hostname`. Сравните это с настройкой имени второй станции в 2.7.

## 2.5. Исследуйте статический интерфейс

```bash
ip -br link
ip -br -4 address
ip -4 route
ifconfig -a
```

Проверьте, какой интерфейс имеет адрес `192.168.101.11/24`, и какой указан в маршруте по умолчанию. Запишите IP и MAC обоих интерфейсов. Имя интерфейса Docker может отличаться от примера из книги.

Измените состояние только внутреннего интерфейса: выключите его, снимите адрес, назначьте тот же адрес вручную и включите снова.

```bash
lan_if=$(ip -o -4 address show | awk '$4 == "192.168.101.11/24" {print $2}')
if [ -n "$lan_if" ]; then
    ethtool "$lan_if"
    ip link set dev "$lan_if" down &&
        ip -br link show dev "$lan_if" &&
        ip address del 192.168.101.11/24 dev "$lan_if" &&
        ip address add 192.168.101.11/24 dev "$lan_if" &&
        ip link set dev "$lan_if" up
    ip -br -4 address show dev "$lan_if"
else
    echo 'Внутренний интерфейс по исходному адресу не найден'
fi
```

Для эксперимента у `wrk1` включена возможность `NET_ADMIN` в его сетевом пространстве. Эти команды меняют текущее состояние контейнера. При пересоздании исходный адрес снова назначит Compose. Подсистемы Etcnet и NetworkManager здесь не управляют интерфейсами, поэтому изменять `/etc/net/ifaces` и перезапускать `network.service` не нужно.

## 2.6. Проверьте внешний маршрут

```bash
ip -4 route show default
ping -c 3 8.8.8.8
```

Сравните внешний интерфейс с внутренним: адрес внешнего выделяет Docker из пула сети, внутренний указан явно в Compose. Это выделение адреса Docker, а не выдача адреса DHCP-сервером внутри контейнера. Если внешний узел не отвечает на ICMP, доступ к репозиторию можно проверить командой `apt-get update`. Этот шаг заменяет проверку тех же параметров в графическом интерфейсе.

## 2.7. Подключите вторую станцию

Из другого терминала **на хосте**, в каталоге с `compose.yaml`:

```bash
docker compose --profile lab01-peer up -d --build lab01-wrk2
docker compose --profile lab01-peer exec lab01-wrk2 bash
```

Внутри второй станции:

```bash
hostname
ip -br link
ip -br -4 address
ping -c 3 192.168.101.11
```

Ожидаются имя `wrk2`, адрес `192.168.101.12/24` на внутреннем интерфейсе и MAC, отличный от `wrk1`. В оболочке первой станции выполните `ping -c 3 192.168.101.12`. Две станции построены из одного Dockerfile, но у каждой свой слой с изменениями. Обновление, выполненное вручную на `wrk1`, не переносится в `wrk2`.

Приложите сравнение RPM до и после обновления, имена и адреса обеих станций, MAC внутренних интерфейсов и результаты двух проверок связности. Объясните, почему версия ядра не меняется после обновления пакетов. Ответьте на контрольные вопросы [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-01.md>), отдельно указав, какие шаги относятся только к виртуальной машине.
