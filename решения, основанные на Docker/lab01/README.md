# Лабораторная работа № 1. Первоначальная настройка ОС

Цель — сравнить состав пакетов до и после обновления и настроить связь между двумя рабочими станциями. Нумерация заданий сохранена из [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-01.md>).

## Предусловия

Стенд подготавливается автоматически при сборке образов и создании контейнеров. Номера заданий указывают, какие шаги методички перенесены в подготовку стенда. Полное сопоставление приведено в [diff.md](diff.md).

### 1. Базовая система и учётная запись (задание 2.1)

[Dockerfile](Dockerfile) использует образ `alt:p11` и создаёт пользователя `admin` с основной группой `admin`, домашним каталогом `/home/admin` и оболочкой Bash. Пароль для `admin` при сборке не задаётся. Для выполнения заданий открывается оболочка от `root` через Compose.

### 2. Установка учебных утилит (подготовка к заданиям 2.1–2.6)

При сборке `apt-get update` скачивает индексы из штатных репозиториев ALT Linux p11. Затем APT устанавливает `apt-repo`, `diffutils`, `ethtool`, `iproute2`, `iputils`, `nano` и `net-tools`. После установки Dockerfile очищает скачанные архивы и индексы. Обновление установленных пакетов студент выполняет в задании 2.2.

### 3. Снимок состояния до обновления (задания 2.1 и 2.3)

После установки утилит Dockerfile создаёт каталог `/home/admin/version_1` с правами `0755` и записывает в него три файла:

| Файл | Что записывается |
| --- | --- |
| `os-release.txt` | Содержимое `/etc/os-release` с номером выпуска ALT Linux. |
| `repositories.txt` | Список используемых репозиториев из вывода `apt-repo`. |
| `packages.txt` | Отсортированный список RPM, установленных в образе, с версиями, релизами и архитектурами. |

Владельцем каталога и файлов становится `admin:admin`. Этот снимок используется для сравнения с `version_2` в задании 2.3.

### 4. Две рабочие станции и их имена (задания 2.4 и 2.7)

[Docker Compose](../compose.yaml) создаёт контейнеры `lab01-wrk1` и `lab01-wrk2` из одного Dockerfile и задаёт им имена хостов `wrk1` и `wrk2`. У каждого контейнера свой слой записи, поэтому изменение пакетов на одной станции применяется только к ней. В каждом контейнере `init: true` включает процесс `init`, а команда `sleep infinity` из Dockerfile удерживает контейнер запущенным между сеансами работы.

### 5. Первичная настройка сети (задания 2.5–2.7)

Compose подключает обе станции к двум сетям:

| Сеть | Назначение и адреса |
| --- | --- |
| `lab01-uplink` | Внешняя bridge-сеть с выходом наружу через Docker. Docker выделяет адреса из пула сети. |
| `lab01-lan` | Изолированная учебная bridge-сеть `192.168.101.0/24`. Статические адреса — `192.168.101.11/24` для `wrk1` и `192.168.101.12/24` для `wrk2`. |

Docker назначает MAC-адреса интерфейсам. Для `wrk1` в Compose добавлена возможность `NET_ADMIN`, чтобы студент мог отключить внутренний интерфейс и заново назначить ему IP в задании 2.5.

## Запуск стенда

Выполните на хосте из каталога с `compose.yaml`:

```bash
docker compose up -d --build lab01-wrk1 lab01-wrk2
docker compose exec lab01-wrk1 bash
```

## Практические задания

Команды выполняйте от `root` внутри `lab01-wrk1`, если в задании не указано другое место запуска.

### 2.1. Просмотрите исходное состояние

Проверьте учётную запись `admin` и просмотрите снимок состояния до обновления:

```bash
id admin
ls -la /etc/apt/sources.list.d
cat /home/admin/version_1/{os-release,repositories}.txt
head /home/admin/version_1/packages.txt
rpm -q apt rpm
```

### 2.2. Обновите пакеты

Проверьте активные источники:

```bash
apt-repo
grep -Eh '^[[:space:]]*rpm[[:space:]]' /etc/apt/sources.list /etc/apt/sources.list.d/*.list
```

Убедитесь, что подключена ветка p11 и нет дублирующих записей. Посмотреть файлы в `/etc/apt/sources.list.d/` можно редактором `nano`. Затем скачайте свежие индексы и выполните обновление:

```bash
apt-get update
apt-get install apt rpm
apt-get dist-upgrade
```

`apt-get update` обновляет индексы, а `dist-upgrade` меняет установленные пакеты. См. [документацию ALT по настройке APT](https://docs.altlinux.org/ru-RU/platform/11.0/html/alt-platform/nastrojka_spiska_repozitoriev_apt.html).

Пункты с Synaptic, Центром управления системой, `update-kernel` и перезагрузкой ОС относятся к стенду на виртуальных машинах. Контейнер использует общее ядро, поэтому обновление пакетов внутри него не обновляет работающее ядро.

### 2.3. Сравните состояние после обновления

После обновления сами создайте второй отчёт и сравните его с первым:

```bash
mkdir -p /home/admin/version_2
cat /etc/os-release > /home/admin/version_2/os-release.txt
apt-repo > /home/admin/version_2/repositories.txt
rpm -qa --qf '%{NAME}-%{VERSION}-%{RELEASE}.%{ARCH}\n' > /home/admin/version_2/packages.txt
LC_ALL=C sort -o /home/admin/version_2/packages.txt /home/admin/version_2/packages.txt
diff -ru /home/admin/version_1 /home/admin/version_2
```

Запишите, что изменилось в версии ALT, списке пакетов и источниках. Отсутствие различий в списке пакетов допустимо, если они уже актуальны для подключённого репозитория. Код выхода `diff` равен 1, если найдены различия.

### 2.4. Проверьте имя рабочей станции

```bash
hostname
cat /etc/hostname
```

Ожидается `wrk1`. Команда `hostname` показывает текущее имя, заданное Compose при создании контейнера. Сравните его с именем второй станции при проверке в задании 2.7.

### 2.5. Исследуйте статический интерфейс

1. Посмотрите адреса, MAC и маршруты:

   ```bash
   ip -br -4 address
   ip -br link
   ip -4 route
   ifconfig -a
   ```

   Найдите интерфейс с адресом `192.168.101.11/24` и сравните его с интерфейсом маршрута по умолчанию. Запишите IP и MAC обоих интерфейсов. В примере внутренний интерфейс называется `eth0`. Если у вас другое имя, подставьте его во все команды ниже. Из записи вида `eth0@if12` берите только `eth0`.

2. Посмотрите характеристики внутреннего интерфейса:

   ```bash
   ethtool eth0
   ```

3. Отключите только внутренний интерфейс и проверьте его состояние:

   ```bash
   ip link set dev eth0 down
   ip -br link show dev eth0
   ```

4. Снимите адрес и убедитесь, что он исчез:

   ```bash
   ip address del 192.168.101.11/24 dev eth0
   ip -br -4 address show dev eth0
   ```

5. Назначьте тот же адрес вручную, включите интерфейс и проверьте результат:

   ```bash
   ip address add 192.168.101.11/24 dev eth0
   ip link set dev eth0 up
   ip -br -4 address show dev eth0
   ```

Команды `ip` меняют текущее состояние контейнера. При пересоздании исходный адрес снова назначит Compose. Подсистемы Etcnet и NetworkManager здесь не управляют интерфейсами, поэтому изменять `/etc/net/ifaces` и перезапускать `network.service` не нужно.

### 2.6. Проверьте внешний маршрут

```bash
ip -4 route show default
ping -c 3 8.8.8.8
```

Сравните адреса интерфейсов. Адрес внешнего интерфейса Docker выделяет из пула сети. Для внутреннего интерфейса адрес задан в Compose. DHCP-сервер в этой схеме не участвует. Если внешний узел не отвечает на ICMP, доступ к репозиторию можно проверить командой `apt-get update`.

### 2.7. Проверьте связь со второй станцией

Вторая станция уже работает. Из другого терминала **на хосте**, в каталоге с `compose.yaml`, откройте её оболочку:

```bash
docker compose exec lab01-wrk2 bash
```

Внутри второй станции:

```bash
hostname
ip -br link
ip -br -4 address
ping -c 3 192.168.101.11
```

Ожидаются имя `wrk2`, адрес `192.168.101.12/24` на внутреннем интерфейсе и MAC, отличный от `wrk1`. В оболочке первой станции выполните `ping -c 3 192.168.101.12`.

### 2.8. Подготовьте отчёт

Приложите сравнение RPM до и после обновления, имена и адреса обеих станций, MAC внутренних интерфейсов и результаты двух проверок связности. Ответьте на контрольные вопросы [исходной методички](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-01.md>), отдельно указав, какие шаги относятся только к виртуальной машине.
