# Лабораторная работа № 2. Управление локальными учётными записями

Цель — проверить сложность и срок действия паролей, блокировку после ошибок входа, смену пароля и удаление локальной учётной записи. Номера заданий соответствуют [исходной методичке](<../../исходники (Прокушев, Я.Е. Информационная безопасность операционных систем Linux : практикум по защите информации)/исходники отцифрованные в md формат/lab-02.md>).

Из каталога с `compose.yaml`:

```bash
docker compose up -d --build lab02 lab02-wrk2
docker compose exec lab02 bash
```

В контейнере `wrk1` [Dockerfile](Dockerfile) устанавливает инструменты входа и смены пароля, применяет политики из [policy/](policy/) и создаёт `user1`–`user4` без заданных паролей. Вы проверяете конфигурацию, задаёте пароли интерактивно и выполняете действия с учётными записями. Не используйте здесь свои настоящие пароли и не записывайте учебные пароли в отчёт.

Оболочку `root` оставьте открытой для административных команд. Для проверки PAM из другого терминала на хосте запускайте `docker compose exec lab02 login user1`, подставляя нужного пользователя. После `exit` из учебной сессии вы вернётесь на хост. Команда `exec --user` запускает процесс с указанным UID без проверки пароля, поэтому для этого задания не подходит.

## 3.1. Проверьте настройки сложности пароля

```bash
cat /etc/passwdqc.conf
```

Найдите `min=24,24,24,12,8`: для паролей из трёх классов требуется не менее 12 символов, из четырёх — не менее 8. `passphrase=0` отключает специальную проверку парольных фраз, `enforce=everyone` применяет требования даже при смене пароля администратором. Найдите также параметры максимальной длины, сравнения со старым паролем и числа попыток выбора нового пароля.

## 3.2. Проверьте политику срока действия

```bash
grep -E '^(PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE|USERDEL_CMD)[[:space:]]' /etc/login.defs
chage -l user1
```

Пароль можно сменить сразу после установки, максимальный срок действия — 91 день, предупреждение начинается за 10 дней. Параметры срока записываются при создании пользователя; для изменения существующей учётной записи используется `chage`. В этом стенде `USERDEL_CMD` очищает запись о неудачных входах удаляемого учебного пользователя.

## 3.3. Найдите параметры блокировки

```bash
cat /etc/security/faillock.conf
```

В доступной копии методички часть задания пропущена. Для стенда задан учебный порог в четыре ошибки за 900 секунд и автоматическая разблокировка через 60 секунд. Порог входа `deny` и число повторов при выборе нового пароля `retry` относятся к разным операциям.

## 3.4. Изучите локальный стек PAM

```bash
cat /etc/pam.d/system-auth-local-only
cat /etc/pam.d/login /etc/pam.d/passwd
```

Найдите типы `auth`, `account`, `password` и `session`. Сервис `login` подключает все четыре части, а команда `passwd` — правила смены пароля. В части `auth` модуль `pam_faillock` проверяет и записывает ошибки входа, в части `password` модуль `pam_passwdqc` проверяет новый пароль. Исходный файл, если он был в образе, сохранён как `/etc/pam.d/system-auth-local-only.original`.

## 3.5. Проверьте учётные записи и задайте пароли

```bash
grep -E '^user[1-4]:' /etc/passwd
ls -ld /home/user{1,2,3,4}
passwd user1
```

Сначала попробуйте ввести слабый учебный пароль, например шесть цифр. Зафиксируйте причину отказа. Затем задайте стойкий учебный пароль: удобно использовать сгенерированную строку от 16 символов с буквами обоих регистров, цифрами и знаками. Задайте отдельные пароли остальным пользователям:

```bash
passwd user2
passwd user3
passwd user4
chage -l user4
chage -d 0 user4
chage -l user4
```

Сравните вывод для `user4` до и после `chage -d 0`: теперь пароль нужно сменить при следующем входе. В записи `/etc/passwd` поле `x` является заполнителем, а не хешем пароля.

## 3.6. Проверьте блокировку и обязательную смену пароля

1. Запустите на хосте `docker compose exec lab02 login user1` и введите неверный пароль четыре раза. Если команда завершится раньше, запустите её снова. До истечения 60 секунд попробуйте войти с верным паролем. После выхода из попытки входа посмотрите счётчик в оболочке `root`:

   ```bash
   faillock --user user1
   ```

   После истечения блокировки повторите вход с верным паролем. Для продолжения работы без ожидания можно снять блокировку вручную: `faillock --user user1 --reset`.

2. Запустите на хосте `docker compose exec lab02 login user4` и введите установленный пароль. PAM должен потребовать смену. Сначала попробуйте вариант, отличающийся только одним символом, затем новый сильный пароль, существенно отличающийся от старого. Зафиксируйте реакцию в обоих случаях.

3. Выйдите из сеанса `user4` командой `exit` и в оболочке `root` выполните `chage -l user4`. Проверьте, что обязательная смена больше не требуется.

## 3.7. Удалите учётную запись

Убедитесь, что сеанс `user4` завершён. От `root` выполните:

```bash
userdel --help
ls -ld /home/user4
userdel -r user4
grep '^user4:' /etc/passwd
test ! -e /home/user4 && echo "Домашний каталог удалён"
```

После удаления `grep` не должен вывести запись. Ключ `-r` удаляет домашний каталог и почтовый ящик; файлы в других каталогах могут остаться.

## 3.8. Смените пароль от имени пользователя

```bash
docker compose exec lab02 login user1
```

После входа выполните `id`. Команда `passwd root` должна отказать в смене чужого пароля. Затем вызовите `passwd` без аргументов, введите текущий пароль и задайте новый. Завершите сеанс командой `exit` и убедитесь, что вход с новым паролем успешен.

## 3.9. Воссоздайте учётную запись

От `root` создайте `user4` заново, назначьте пароль и проверьте запись, домашний каталог и срок действия:

```bash
useradd -U -m -s /bin/bash -G users -c 'Сергей Сергеев' user4
passwd user4
id user4
ls -ld /home/user4
chage -l user4
```

## 3.10–3.11. Повторите настройку на `wrk2`

Вторая станция уже работает. Откройте её оболочку в отдельном терминале из каталога с `compose.yaml`:

```bash
docker compose exec lab02-wrk2 bash
```

Здесь установлены те же инструменты, но учебные настройки и пользователи ещё не созданы. Посмотрите шаблоны в `/usr/local/share/lab02`, примените настройки командой `bash /usr/local/share/lab02/configure.sh` и сверьте значения по заданиям 3.1–3.4. Затем самостоятельно создайте `user1`–`user4` через `useradd` по образцу 3.9, задайте им те же учебные пароли, что действуют на `wrk1`, и проверьте вход с хоста командой `docker compose exec lab02-wrk2 login user1`.
