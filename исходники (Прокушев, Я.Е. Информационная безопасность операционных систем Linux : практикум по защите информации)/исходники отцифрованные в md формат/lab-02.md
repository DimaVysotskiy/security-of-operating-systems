Команда **man** с последующим указанием интересующего вас системного файла или команды предоставляет справочную информацию о запрошенном объекте.

Рассмотрим некоторые параметры парольной политики, комментарии к которым приведены в справке к passwdqc.conf:

- N0 используется для паролей, состоящих только из символов одного класса. Классами символов являются: цифры, строчные буквы, прописные буквы и другие символы. То есть в таком пароле используется только один тип символов.
- N1 используется для паролей, состоящих из символов двух классов, которые не соответствуют требованиям к парольной фразе.
- N2 используется для парольных фраз. Кроме соответствия требованию к длине, парольная фраза также должна состоять из достаточного количества слов (этот параметр будет рассмотрен ниже).

<!-- Источник: 20261028_141143.jpg; стр. 61 -->

- N3 и N4 используются для паролей, состоящих из символов трех и четырех классов соответственно. При подсчете количества классов символов заглавные буквы, используемые в качестве первого символа, и цифры, используемые в качестве последнего символа пароля, не учитываются. Помимо того, что пароли должны быть достаточно длинными, они должны содержать достаточное количество различных символов классов и обладать минимальной длиной, на которую должны быть проверены.
- max — это максимально допустимая длина пароля. Она может быть использована для предотвращения установки пользователями паролей, которые могут быть слишком длинными для некоторых системных служб. Значение 8 обрабатывается особым образом: если max установлена равной 8, пароли длиной более 8 символов не будут отклонены, но будут сокращены до 8 символов для проверки надежности, и пользователь будет предупрежден.
- passphrase — это количество слов, требуемое для ключевой фразы. Если указать значение 0, то формирование пароля на основе фраз будет отключено.
- match = N — это длина общей подстроки, необходимая для вывода сообщения о том, что пароль по крайней мере частично основан на информации, найденной в символьной строке. Значение 0 отключает поиск по подстроке.
- similar = permit | deny — опция определяет, разрешено ли новому паролю быть похожим на старый. Пароли считаются похожими, когда имеется достаточно длинная общая подстрока, а новый пароль с частично обесцененной подстрокой был бы слабым.
- enforce = none | users | everyone — это опция из PAM-модуля. Она не позволяет использовать слабые пароли. Значение none указывает на то, что параметр не применяется ни к одному типу учетных записей, users — только к пользователям, а everyone — ко всем учетным записям.

Рис. 3.4. Структура pam-файла по умолчанию

Каждая строка файла состоит из четырех полей, разделенных пробелами или знаками табуляции: тип, обязательность выполнения модуля, наименование модуля, параметры работы модуля:

<!-- Источник: 20261028_141212.jpg; стр. 67 -->

- Выполняемый тип запроса к PAM. Существует четыре типа запросов:

  1. auth осуществляет проверку данных входа, например логина и пароля;
  2. account проверяет срок действия учетной записи;
  3. password контролирует обновление пароля;
  4. session контролирует обслуживание сессии. Например, ведение аудита действий пользователя.

- Второе поле файла определяет обязательность выполнения модуля (действие, которое нужно выполнить после вызова данного модуля):

  - свойство required должно вернуть положительный ответ. Если результат вызова модуля возвращает отрицательный ответ, то произойдет ошибка аутентификации. Запрос будет сброшен, но остальные модули будут вызваны;
  - свойство requisite — аналог required, который, однако, сразу же приводит к сбою аутентификации в случае ошибки и игнорирует остальные модули;
  - если перед инструкцией sufficient ни одна из инструкций не вернула отрицательного результата, то вернется положительный ответ, а оставшиеся модули будут проигнорированы;
  - если используется инструкция optional, а в стеке нет команд required и ни один из модулей sufficient не вернул положительного результата, то хотя бы один из модулей optional должен вернуть положительный ответ. В этом случае стек команд отработает успешно;
  - инструкция include позволяет добавлять строки из других сценариев конфигурации.

Также в качестве действий могут быть указаны такие значения:

- ignore — не влияет на общий код возврата в приложение;
- bad — значение расценивается как свидетельство сбоя модуля;
- die — аналогично bad, но сразу возвращает управление в приложение;
- ok — значение влияет на общий возвращаемый результат и переопределяет общий результат, если он раньше был успешен, но не отменяет сбой;
- done — аналогично ok, только управление сразу возвращается приложению.

<!-- Источник: 20261028_141218.jpg; стр. 68 -->

- Третий параметр — это путь к вызываемому модулю.
- Четвертый параметр — это опциональные параметры модуля. Это необязательные параметры, однако они в ряде случаев необходимы, чтобы определить настройки работы модуля.

Рис. 3.6. Содержимое файла /etc/passwd

- **символ x** — зашифрованное отображение парольной фразы. Для работы с паролями используется команда passwd;
- **идентификационный номер пользователя** (User ID, UID) — уникальный номер пользователя. Отметим, что операционная система работает именно с идентификационными номерами, а не с именами (имена используют люди);
- **идентификационный номер группы** (group ID) обозначает группу, к которой по умолчанию относится пользователь. С помощью групп удобно администрировать доступ пользователей к защищаемым ресурсам. Каждый пользователь может принадлежать к одной или нескольким группам;
- **полное имя пользователя**. Например, system administrator, Ivan Ivanov;
- **домашний каталог** (home directory) — это каталог (папка), где хранятся собственные файлы пользователя. Домашние каталоги пользователей находятся в папке /home;

### Задание 3.7. Выполните удаление учетной записи

**Выполнение:**

> Для удаления учетной записи используется команда userdel.

Префикс -r используется для того, чтобы удалить все каталоги и файлы (домашний каталог и другие объекты), которые связаны с удаляемым пользователем. Кроме того, в файле /etc/login.defs можно включить настройку USERDEL_CMD для очистки объектов, связанных с удаляемым пользователем.

При создании пользователей были сформированы их личные каталоги в папке /home. Просмотрите содержание каталога с помощью команды **ls -l**, как показано на рисунке 3.15.


Команда **cat** выводит содержимое файла на экран, а команда **grep** отфильтровывает результат и оставляет только те записи, где встречается слово user.

В появившемся списке учетной записи user4 быть не должно. Также проверьте наличие каталога /home/user4. Его также быть не должно. В ряде случаев команда userdel может не выполниться успешно. Одной из причин такого явления могут быть процессы, открытые от имени удаляемого пользователя. В этом случае надо проверить их наличие. Например, если осуществляется проверка процессов, запущенных от имени пользователя admin, то команда проверки будет выглядеть следующим образом [41]:

```text
wrk11 ~ # ps -u admin
```

Появится таблица со списком процессов, запущенных от имени пользователя. В столбце PID будут указаны идентификаторы процессов. Процесс можно прервать (прекратить выполнение) с помощью команды:

```text
kill -options номер_PID
```

```text
kill -9 номер_PID
```
