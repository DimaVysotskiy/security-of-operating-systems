# Раздел 7. Осуществление контроля целостности объектов информационной системы

<!-- Источник: 20261028_143036.jpg; стр. 132 -->

## 7.1. Цель раздела

**Цель раздела** — получение практических навыков использования модуля *Проверка целостности*, входящего в *Alterator*.

## 7.2. Теоретическая информация

> **Контроль целостности информации** — это методы и средства, которые позволяют обнаруживать несанкционированные случайные или умышленные изменения защищаемых объектов в информационной системе.

Для контроля и защиты данных от случайных повреждений или намеренного искажения, как правило, используются криптографические алгоритмы хеширования данных или электронной подписи.

Контроль (проверка) целостности является одной из важнейших процедур, которые должны выполняться в процессе функционирования защищенной операционной системы. Контроль целостности позволяет обнаруживать несанкционированные изменения в защищаемой системе.

Для обеспечения контроля целостности в операционной системе ОС Alt Linux предусмотрен модуль *Проверка целостности*, который устанавливается с помощью пакета *alterator-osec* [49].

<!-- Источник: 20261028_143039.jpg; стр. 133 -->

Модуль *Проверка целостности* обладает следующими возможностями:

- позволяет произвольно выбирать объекты файловой системы для контроля;
- выполняет периодический контроль целостности защищаемой системы;
- формирует отчетность о результатах проводимых проверок;
- запускает проверку «по требованию» объектов защищаемой системы;
- предоставляет информацию о ходе выполнения проверки;
- предоставляет информацию о результатах произведенных проверок.

Своевременно выполняемая проверка целостности позволяет предотвратить или минимизировать ущерб от несанкционированных изменений, произошедших в системе. Возможностью обеспечения контроля целостности произвольно заданных объектов обладают не все операционные системы. В частности, в операционных системах семейства Windows проверяется только целостность файлов ядра на этапе загрузки.

Встроенные возможности утилиты ***Проверка целостности*** не позволяют реализовать данную задачу в полной мере. Поэтому для расширения возможностей осуществления механизма контроля целостности будет использован сервис **cron**. Кратко рассмотрим некоторые элементы данного сервиса.

> **Cron** — это планировщик заданий, который работает в Linux-системах. Он обеспечивает автоматическое выполнение требуемых администратором действий (запуск программ, скриптов и т.п.), с заданным временем или периодичностью.

Первые версии этого сервиса были разработаны еще в 70-х годах XX столетия. Доступ к настройке *cron* по умолчанию имеет учетная запись ***root***. Для регулирования возможности работы с *cron* других пользователей имеются настроечные файлы:

- */etc/cron.allow* — создается для предоставления пользователям возможности запуска заданий планировщика. По умолчанию данный файл отсутствует в ОС *Alt Linux*. Если файл *cron.allow* существует, то только учетным записям, перечисленным в нем, разрешено использовать *cron*. Настройки файла *cron.deny* в этом случае игнорируются;
- */etc/cron.deny* — используется для блокировки возможности запуска заданий планировщика теми пользователями, которые указаны в данном файле. По умолчанию данный файл имеется в ОС *Alt Linux*.

При заполнении этих файлов пользователи указываются построчно. В каждой строке пишется имя одного пользователя. Пробелы не разрешаются. Обращение к этим файлам происходит каждый раз, когда пользователь пытается добавить или удалить задачу *cron* [52].

Настройки *cron* хранятся в файле */etc/crontab*.

В некоторых ОС семейства Linux допускается добавлять задания с помощью редактирования данного файла. Однако более предпочтительным способом является использование утилиты **crontab** [12]. Она запускается с определенными ключами, регулирующими поведение данной команды:

- *crontab -e* создает новые задания.

<!-- Источник: 20261028_143110.jpg; стр. 143 -->

  После завершения редактирования шаблон задания будет обработан, и все правила сохранятся в файл */var/spool/cron/имя_пользователя*. Причем добавленные процессы будут запускаться именно от того пользователя, который создавал задания. Если задания создавались от имени учетной записи *root*, то и права у данного задания будут не ограничены;
- *crontab -r* позволяет удалять задания;
- *crontab -l* используется для просмотра созданных заданий;
- *crontab -s* используется для работы с заданиями с учетом подсистемы sylinux.

Также в ОС Alt Linux имеются каталоги, в которых размещаются скрипты, выполняемые с определенной периодичностью:

- в каталоге */etc/cron.daily* размещаются скрипты, выполняемые ежедневно;
- в каталоге */etc/cron.hourly* размещены скрипты, которые должны запускаться каждый час;
- в каталоге */etc/cron.weekly* размещены скрипты, которые должны запускаться каждую неделю;
- в каталоге */etc/cron.monthly* размещены скрипты, которые должны запускаться каждый месяц.
- в каталоге */etc/cron.d* размещены задания, которые были созданы различными приложениями.

Отметим, что в зависимости от конкретной операционной системы семейства Linux наличие некоторых каталогов и файлов может несколько отличаться от перечисленного выше списка.

### Задание 7.6. Настроить сервис cron для выполнения процедуры контроля целостности

**Выполнение:**

<!-- Источник: 20261028_143120.jpg; стр. 144 -->

1. Работая в командной строке под учетной записью администратора, выполните команду:

   ```text
   wrk1 ~ # crontab -e
   ```

   В установленном по умолчанию редакторе (*vim* или *nano*) откроется временный файл (рис. 7.9), основанный на файле шаблона */etc/crontab.template*. Рассмотрим его структуру.

   ```text
   #minute (0-59),
   #|       hour (0-23),
   #|       |         day of the month (1-31),
   #|       |         |         month of the year (1-12),
   #|       |         |         |         day of the week (0-6 with 0=Sunday),
   #|       |         |         |         |         commands
   ```

   Рис. 7.9. Шаблон для создания нового задания

   Все строки шаблона по умолчанию закомментированы — в начале строки установлен символ решетки #. Синтаксис создаваемого задания будет выглядеть следующим образом:

   ```text
   минута час день месяц день_недели /путь/к/исполняемому/файлу
   ```

   Временные элементы могут принимать значения в соответствии с общепринятым времяисчислением:

   - минута — от 0 до 59;
   - час — от 0 до 23;
   - день — от 1 до 31;
   - месяц — от 1 до 12;
   - день недели — от 1 до 7;
   - путь к исполняемому файлу — это полный путь к скрипту или программе.

   Символ звездочки (*) вместо указанного значения означает выполнение команды каждый промежуток времени — минуту/час/день/неделю/месяц.

<!-- Источник: 20261028_143123.jpg; стр. 145 -->

Кроме того, имеется возможность указать следующие значения, регулирующие запуск программ:

- @reboot — при загрузке;
- @hourly — каждый час;
- @daily — каждый день;
- @weekly — раз в неделю;
- @monthly — раз в месяц;
- @yearly, @annually — раз год.

Например, если требуется запускать каждый день в 12 часов 45 минут программу *nano*, то в окне редактора заданий следует ввести такую последовательность:

```text
45 12 * * * /usr/bin/nano
```

Теперь следует определиться с файлом, который будет запускаться. Запуск заданий контроля целостности выполняет скрипт */etc/osec/run-osec*. Этот файл будет указан в задании. Если после выполнения *crontab -e* открылся файл в редакторе ***vi***, нажмите на клавиатуре букву *i*. Команда переведет редактор в режим вставки данных. Чтобы перейти назад в командный режим, следует нажать клавишу **Tab**.

2. В открытом файле добавьте две строки — будет предусмотрено выполнение двух заданий. Первое будет запускаться при загрузке операционной системы. Для запуска второго задания выберем время в интервале обеденного перерыва — 13 часов 10 минут (будем считать, что пользователи уходят на обед с 13 до 14 часов).

   Укажите параметры запуска заданий, как показано на рисунке 7.10.

   ```text
   #minute (0-59),
   #|       hour (0-23),
   #|       |         day of the month (1-31),
   #|       |         |         month of the year (1-12),
   #|       |         |         |         day of the week (0-6 with 0=Sunday).
   @reboot /etc/osec/run-osec
   10 13 * * * /etc/osec/run-osec
   #|       |         |         |         |         commands
   ```

   Рис. 7.10. Настройка выполнения заданий контроля целостности

Сохраните изменения в файле (команда **:w**).

3. Закройте файл с сохранением изменений (команда **:q**).

   Обратите внимание на то, что в окне программы **Терминал** появилась запись о добавлении заданий контроля целостности:

   ```text
   crontab: installing new crontab
   ```

4. Откройте каталог */var/spool/cron*. В нем появится файл *root*, где сохранены графики выполнения заданий. Ознакомьтесь с его содержимым, но не меняйте.
5. Файл со сформированным расписанием контроля целостности поместите в отчет о выполнении практических заданий. Закройте файл.

> **ВНИМАНИЕ!**
>
> Напоминаем, что файл, запускающий задание с правами ***root***, будет иметь неограниченные права доступа. Добавлять инструкции в него следует предельно внимательно и осторожно.

6. Внесите изменения в объекты из каталога */home/test3*, которые были созданы ранее для отработки заданий контроля целостности.
7. Перезагрузите компьютер.
8. Откройте окно модуля *Контроль целостности*. Должна появиться запись о событии контроля целостности во время загрузки. В описании должна содержаться информация об обнаружении изменений в файлах.

Отметим, что в данном случае никакой реакции со стороны операционной системы на нарушение целостности проверяемых объектов не происходит. Более того, после выполнения нескольких процедур контроля целостности информация об обнаруженных нарушениях исчезнет, поскольку журналы событий перезаписываются.

Чтобы перезапись не происходила, необходима ручная правка некоторых файлов Alt Linux.

Таким образом, после каждого выполнения контроля целостности возникает дополнительная задача переноса данных отчета или их фиксации в каком-то другом, специально предназначенном для данной цели объекте.

Чтобы имелась возможность отправки отчетов по почте, вверху окна настройки контроля целостности следует установить флажок **Отправлять отчет** (рис. 7.3). Затем следует настроить отправку сообщения администратору через почтовый сервер. В полном объеме возможности модуля контроля целостности реализованы в версии Alt Linux 8 СП.
