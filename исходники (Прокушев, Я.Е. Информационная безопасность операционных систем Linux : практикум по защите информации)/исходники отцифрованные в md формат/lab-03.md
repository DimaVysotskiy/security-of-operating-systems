# Раздел 4. Работа с группами учетных записей

<!-- Источник: 20261028_141951.jpg; стр. 82 -->

## 4.1. Цель раздела

**Цель раздела** — получить теоретические знания и базовые навыки управления группами учетных записей.

## 4.2. Теоретическая информация

Объединение учетных записей в группы позволяет существенно облегчить процесс администрирования и управления доступом пользователей к ресурсам защищаемого компьютера. Поэтому в операционной системе предусмотрен механизм использования групп. Некоторые из них являются системными и создаются по умолчанию при установке операционной системы. Они изначально обладают определенными правами.

Другие группы администратор может создать сам. Например, для управления правами доступа пользователей к объектам файловой системы.

Одна учетная запись может входить в несколько групп, в то же время в одной группе может быть несколько учетных записей. В группы включают пользователей, имеющих одинаковые или весьма похожие права. В операционных системах семейства Linux можно выделить:

- системные группы. Они предусмотрены особенностями операционной системы и существуют по умолчанию сразу после ее установки (root, bin, sys, disk, wheel и т.п.). Некоторые группы, создаваемые на этапе инсталляции операционной системы, представлены в таблице 4.1 [33].

<!-- Источник: 20261028_141953.jpg; стр. 83 -->

Таблица 4.1. Некоторые системные группы пользователей в Alt Linux

| Группа | Краткая характеристика |
| --- | --- |
| root | Полный доступ к администрированию и управлению системой |
| adm | Предоставляет доступ к директории /var/log/. Группа администрирования, которая обычно используется для чтения файлов защищенных логов. Позволяет читать файлы журнала |
| daemon | От имени этой группы и пользователя daemon запускаются сервисы, которым необходима возможность записи файлов на диск |
| sys | Группа открывает доступ к исходникам ядра и файлам include, сохраненным в системе |
| man | Позволяет добавлять страницы в директорию /var/cache/man |
| mail | Позволяет записывать данные в почтовые ящики /var/mail/ |
| tty | Все устройства /dev/vca дают доступ на чтение и запись пользователям из этой группы |
| disk | Открывает доступ к жестким дискам `/dev/sd* /dev/hd*`, не затронутым другими группами, такими как optical, floppy и storage |
| cdrom | Доступ к CD-ROM |
| wheel | Позволяет запускать утилиту sudo для повышения привилегий |
| audio | Управление аудиодрайвером |
| shadow | Разрешает чтение файла /etc/shadow |
| video | Позволяет работать с видеодрайвером |
| plugdev | Позволяет монтировать внешние устройства USB, CD и т.д. |

- группы, созданные для обеспечения функционирования определенных программ или процессов (psqluser, snort, vboxusers);
- группы, созданные администратором для управления доступом пользователей к ресурсам (например, группа, объединяющая менеджеров, финансистов, сотрудников ИТ отдела и т.п.);
- группы, автоматически появляющиеся после создания учетных записей пользователей (совпадают с именем соответствующей учетной записи пользователя).

<!-- Источник: 20261028_141958.jpg; стр. 84 -->

По умолчанию такая группа будет являться основной для данного пользователя. Других пользователей в этой группе по умолчанию нет. Такие группы редко используются при настройке прав доступа к объектам.

По этой причине создаются пользовательские группы, в которые затем добавляются учетные записи.

## 4.3. Практические задания

### Задание 4.1. Просмотрите список групп на компьютере

**Выполнение:**

1. Запустите программу **Терминал**.
2. Выполните в терминале команду:

```text
wrk11 ~ # nano /etc/group или vim /etc/group
```

Рассмотрим структуру файла /etc/group, фрагмент которого представлен на рисунке 4.1.

```text
root:x:0:
bin:x:1:root
daemon:x:2:root
sys:x:3:root,bin,adm
adm:x:4:root
tty:x:5:
disk:x:6:root
lp:x:7:
mem:x:8:
kmem:x:9:
wheel:x:10:root,admin
firewall:x:11:
mail:x:12:
..............................
sambashare:x:450:admin
admin:x:500:
psqluser:x:449:
managers:x:504:
snort:x:448:
mailadm:x:447:
user1:x:501:
user2:x:502:
user3:x:503:
```

Рис. 4.1. Фрагмент содержимого файла /etc/group

Первое поле определяет имя группы, второе поле — это поле остаточного пароля, которое зарезервировано ОС (выглядит как x). Третье поле определяет числовой идентификатор для конкретной группы.

Четвертое поле определяет всех членов группы, в нее входящих.

<!-- Источник: 20261028_142001.jpg; стр. 85 -->

> **ВНИМАНИЕ!**
>
> Обратите внимание на группу *wheel*. Члены этой группы имеют право повышать свои права, выполняя команду **su -** в процессе работы в консоли, с последующим указанием пароля ***root***. Это дает им возможность выполнять в дальнейшем действия по администрированию системы.

При создании пользователя для него создается первичная (основная) группа с таким же именем. Например, есть группы user1, user2 и т.д.

Также пользователь может входить в состав нескольких дополнительных групп (их количество не ограничено). Первичная группа отличается от дополнительных тем, что для всех файлов в домашнем каталоге пользователя в качестве субъекта доступа указана эта первичная группа. При смене пользователей группа, указанная в качестве субъекта доступа для этих каталогов, тоже поменяется. Именно первичную группу в качестве субъекта доступа получают все файлы, созданные пользователем. Дополнительные группы нужны, чтобы была возможность разрешить пользователям доступ к разным ресурсам. С этой целью пользователей и добавляют в них. Отметим, что первичную группу можно поменять.

3. Откройте второй экземпляр программы **Терминал** для одновременного просмотра файлов /etc/passwd и /etc/group. Обратите внимание на то, что в файле /etc/passwd указаны идентификаторы основных групп. При этом имеют место совпадения номеров идентификаторов групп и пользователей. Отметим, что номера uid (User identifier) созданных пользователей admin, user1 и т.п. начинаются со значения 500. Аналогичная ситуация наблюдается и со значениями gid (Group identifier) групп.

### Задание 4.2. Выполните создание пользовательских групп

**Выполнение:**

1. В программе **Терминал**, работая с правами учетной записи *root*, введите команду с ключом -h или вообще без параметров:

```text
wrk1 ~ # groupadd -h
```

<!-- Источник: 20261028_142007.jpg; стр. 86 -->

2. Откроется справочная информация о возможных для использования ключах этой команды. Ознакомьтесь с содержимым справки. В данном случае будут созданы группы без каких-либо ключей.
3. Создайте группу managers с помощью команды:

```text
wrk1 ~ # groupadd managers
```

4. Самостоятельно создайте группу specialists.
5. Самостоятельно создайте группу tests.

### Задание 4.3. Выполните добавление пользователей в группы

**Выполнение:**

1. Выполните команду usermod с ключом -h или без каких-либо командных ключей. Откроется перечень ключей, с помощью которых можно изменить состояние учетной записи. Изучите их.

```text
wrk1 ~ # usermod -h
```

Для добавления пользователя в группу без изменения других его параметров и вхождений в другие группы следует использовать ключ -a.

Выполните команду groups для проверки принадлежности пользователя к группам:

```text
wrk1 ~ # groups user1
```

Также попробуйте использовать команду id:

```text
wrk1 ~ # id user1
```

В случае применения команды id дополнительно выводится информация о gid групп, в которые входит пользователь. Выполним команду добавления пользователя user1 в группу managers (не первичную) сначала без ключа -a.

<!-- Источник: 20261028_142009.jpg; стр. 87 -->

```text
wrk1 ~ # usermod -G managers user1
```

2. Снова проверьте принадлежность пользователя user1 к другим группам с помощью команды:

```text
wrk1 ~ # id user1
```

Отобразится принадлежность пользователя к основной группе user1 и только к одной дополнительной группе managers. Без добавления ключа -a и использования опции g происходит затирание предыдущей принадлежности пользователя к дополнительным группам и переназначение к новым, указанным в списке команд. Теперь выполним добавление пользователя user2 в группу managers, но с использованием ключа -a.

```text
wrk1 ~ # id user2
wrk1 ~ # usermod -a -G managers user2
wrk1 ~ # id user2
```

3. Сравните итоги применения опции -G. Для исправления ситуации следует выполнить команды (порядок ключей имеет значение):

```text
wrk1 ~ # usermod -a -G users user1
```

4. Чтобы группа **managers** являлась первичной для пользователя user1, выполните команду:

```text
wrk1 ~ # usermod -g managers user1
```

5. Для пользователя user2 также назначьте первичную группу managers.
6. Самостоятельно добавьте пользователей user3 и user4 в группу specialists так, чтобы не было удалено их членство в других пользовательских группах. Итог добавления учетных записей в созданные группы показан на рисунке 4.2 (просмотр также можно выполнить с использованием команды id). Описание групп доступно в электронном документе [30].

<!-- Источник: 20261028_142033.jpg; стр. 88 -->

```text
wrk1 ~ # groups user1
user1 : user1 users managers cdwriter cdrom audio video proc radio
 camera floppy xgrp scanner uucp vboxusers fuse vboxadd vboxsf
wrk1 ~ # groups user2
user2 : user2 users managers cdwriter cdrom audio video proc radio
dio camera floppy xgrp scanner uucp vboxusers fuse vboxadd vboxsf
wrk1 ~ # groups user3
user3 : user3 users specialists cdwriter cdrom audio video proc ra
dio camera floppy xgrp scanner uucp vboxusers fuse vboxadd vboxsf
```

**Выполнение:**

1. Самостоятельно добавьте учетные записи user2, user3 с ключом -a в дополнительную группу tests.
2. Проверьте выполнение результатов с помощью команд id.

4. Для удаления пользователя из членства в группе может использоваться команда gpasswd с ключом -d со следующим синтаксисом:

```text
gpasswd -d имя_пользователя группа
```

Для удаления пользователей user2 и user3 из группы tests выполните команды:

```text
wrk1 ~ # gpasswd -d user2 tests
wrk1 ~ # gpasswd -d user3 tests
```

В случае успешного удаления пользователя из группы появится соответствующее сообщение.

5. Снова проверьте принадлежность пользователей user3 и user2 к группам. Среди групп, в которые входят данные пользователи, группы tests быть не должно.
6. Удалите группу tests. Для этого последовательно введите команды сначала удаления пользователя tests, а затем группы tests.
7. Во многих операционных системах семейства Linux при создании групп создается и учетная запись с таким же именем. Поэтому сначала выполним команду удаления пользователя с таким же, как и группы, именем. В данном случае пользователя tests:

```text
wrk1 ~ # userdel -r tests
wrk1 ~ # groupdel -f tests
```

В ОС Alt Linux имеется возможность управления группами пользователей с помощью графического интерфейса. Для доступа к нему следует открыть **Центр управления системой**, указав пароль пользователя *root*, а затем в открывшемся окне выбрать пункт **Локальные группы** (рис. 4.4).
